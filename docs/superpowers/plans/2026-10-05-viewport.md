# Viewport Implementation Plan

> Execute inline with superpowers:executing-plans; use test-driven development for filtering and adapters, and verification-before-completion for the handoff.

**Goal:** Deliver the user's GitHub Pages discovery/filtering milestone.
**Architecture:** A static TypeScript app with pure content filters and replaceable catalog, availability, and launch adapters. Local preferences only.
**Tech Stack:** Vite 7, TypeScript 5.9, Node's test runner, semantic HTML, CSS, original SVG art.
**Spec:** ../specs/2026-10-05-viewport-design.md

## Global constraints

No scraping, backend, accounts, payments, commercial subscriptions, or native exact-title launch claims. Twenty sample entries. Clearly label simulated offers and annotations. Treat artwork and content independently. Target desktop and iPad, support mobile and keyboard.

## Review focus

- Storage unavailable or corrupt: usable app, honest persistence status.
- No selected services: helpful empty state, no unrelated offers.
- Restricted maturity and unknown classification: exclude unknown unless explicitly allowed.
- Filters change while details open: excluded titles disappear from all surfaces.
- External links: provider-specific official HTTPS homepage only; no fabricated title support.
